# MVP Weight Management Design

Last updated: 2026-05-30

## Goal

MVPの目的は、ユーザーが体重を継続的に記録し、日々の増減に振り回されず、7日平均とトレンドで減量の進み具合を理解できる状態を作ること。

この機能は、将来的な運動提案・食事提案・モチベーション機能の土台になる。

## User problem

ユーザーは運動をしているのに体重が落ちないと感じている。しかし実際には、以下の問題が混ざっている可能性が高い。

- 単日の体重増減に一喜一憂している
- 体重の7日平均を見ていない
- 食事や運動の変更が、体重トレンドにどう影響しているか見えていない
- 記録が続かず、判断材料が不足している
- 停滞期に「もう無理」と感じやすい

MVPでは、まず体重データの蓄積と解釈に集中する。

## Core user stories

- ユーザーとして、朝に10秒以内で体重を記録したい。
- ユーザーとして、今日の体重が昨日より増えても、問題があるのか一時的なブレなのか知りたい。
- ユーザーとして、7日平均が下がっているかをすぐ確認したい。
- ユーザーとして、目標体重までの進捗を見たい。
- ユーザーとして、入力を忘れた日もあとから記録したい。
- ユーザーとして、間違って入力した体重を編集・削除したい。
- ユーザーとして、停滞している時に何を見直せばいいか知りたい。

## Non-goals for MVP

- 詳細な食事記録
- 食材ごとのカロリー検索
- 運動メニュー自動最適化
- ウェアラブル連携
- AIチャット
- 写真による体型比較
- 友達共有やランキング

## Onboarding

初回起動時に以下を入力する。

| Item | Required | Example | Notes |
| --- | --- | --- | --- |
| 性別 | Yes | 男性 | 消費カロリー推定に使う |
| 年齢 | Yes | 30 | 生年月日でもよい |
| 身長 | Yes | 167cm | BMI計算に使う |
| 現在体重 | Yes | 80.0kg | 初期値として登録 |
| 目標体重 | Yes | 70.0kg | 後から変更可能 |
| 目標ペース | Yes | 週0.4kg | 初期推奨は週0.4から0.7kg |
| 体重測定タイミング | No | 起床後 | コーチコメントに使う |

初期ユーザー向けの推奨値。

- 身長: 167cm
- 現在体重: 80.0kg
- BMI: 約28.7
- 初期目標: まず75.0kg
- 中期目標: 70.0kg
- 推奨ペース: 週0.4から0.7kg

## Main screens

### Home

毎日起動する画面。情報量は絞り、今日の状態が一目でわかるようにする。

表示項目。

- 今日の体重入力カード
- 今日の体重
- 7日平均体重
- 前週比
- 目標までの残りkg
- コーチコメント
- 入力ストリーク
- 直近7日ミニグラフ

体重入力前の表示例。

```text
今日の体重を記録しましょう
前回: 79.6kg
7日平均: 79.8kg
```

体重入力後の表示例。

```text
今日: 79.9kg
7日平均: 79.7kg
前週比: -0.4kg

順調です。今日の体重は少し増えていますが、7日平均は下がっています。
見るべき数字はこっちです。
```

### Weight chart

体重の推移を確認する画面。

表示する系列。

- 日々の体重
- 7日移動平均
- 目標ライン

期間切り替え。

- 7日
- 30日
- 90日
- 全期間

表示方針。

- 日々の体重は薄く表示する
- 7日平均を太く表示する
- 単日の増減より、傾きを見せる
- 目標ラインはプレッシャーになりすぎない見た目にする

### Weight entry

体重入力の画面またはボトムシート。

入力項目。

- 測定日
- 体重
- メモ 任意

入力UI。

- 前回体重を初期値にする
- `+0.1kg` / `-0.1kg` のステッパーを用意する
- キーボード直接入力も可能にする
- 保存後はすぐホームに戻す

バリデーション。

- 体重は30.0kgから250.0kg
- 小数1桁を基本表示にする
- 同じ日に複数入力がある場合は、代表値を1つ選ぶ

### Weekly review

週に1回、トレンドを振り返る画面。

表示項目。

- 今週の平均体重
- 先週との差分
- 入力日数
- 最も軽かった日
- 目標ペースとの差
- 来週の一言アドバイス

レビュー例。

```text
今週の7日平均は -0.5kg です。
目標ペース内でかなり良い進み方です。
このまま食事量を大きく変えず、平日1時間の運動を継続しましょう。
```

## Derived metrics

派生値は最初は保存せず、表示時に計算する。処理が重くなったらキャッシュを検討する。

### BMI

```text
BMI = weight_kg / (height_m * height_m)
```

167cm, 80kgの場合。

```text
80 / 1.67 / 1.67 = 28.7
```

### 7-day moving average

対象日を含む直近7日分の代表体重の平均を使う。

ルール。

- 同日に複数記録がある場合は、原則として最初の記録を代表値にする
- 直近7日のうち3日未満しか記録がない場合は「データ不足」と表示する
- 4日以上あれば参考値として表示する

### Weekly trend

今日の7日平均と、7日前時点の7日平均を比較する。

```text
weekly_trend = current_7day_average - previous_7day_average
```

判定。

| Weekly trend | Label | Meaning |
| --- | --- | --- |
| -0.8kg以下 | 速すぎる可能性 | 食事を削りすぎていないか確認 |
| -0.7kgから-0.3kg | 理想範囲 | かなり良いペース |
| -0.3kgから-0.1kg | ゆるやかに減少 | 継続でよい |
| -0.1kgから+0.1kg | 横ばい | 2週間続くなら調整 |
| +0.1kg以上 | 増加傾向 | 食事量、塩分、運動量を確認 |

初期ユーザーの場合、80kg前後なので週0.4から0.7kg減を理想範囲にする。

## Coach comment logic

コーチコメントは、以下の情報から生成する。

- 今日の体重
- 前回体重
- 7日平均
- 7日前の7日平均
- 入力継続日数
- 目標ペース
- データ不足の有無

コメントの原則。

- 単日増加を責めない
- 7日平均を中心に説明する
- 次に見るべき指標を示す
- アドバイスは1つに絞る
- 体重が落ちた日だけでなく、入力行動も評価する

コメント例。

```text
体重は昨日より増えていますが、7日平均は下がっています。順調です。
今日は数字に振り回されず、いつもの食事と運動を続けましょう。
```

```text
7日平均が2週間ほぼ横ばいです。
まずは食事を大きく崩さず、夕食の脂質か間食を1つだけ見直しましょう。
```

```text
入力が3日続いています。これはかなり大事です。
体重を落とす前に、体重を見続けられる状態を作れています。
```

## Motivation design

褒める対象。

- 体重を入力した
- 3日以上入力が続いた
- 7日平均が下がった
- 目標ペース内に入った
- 停滞中でも記録を続けた
- 前月より体重のブレが小さくなった

避ける表現。

- 単日増加を失敗として扱う
- 食べすぎを責める
- 根拠なく「脂肪が増えた」と断定する
- 毎日テンションが高すぎる文面にする

## Empty states

初回。

```text
まずは今日の体重を記録しましょう。
1日分だけでも、ここから減量の地図が作れます。
```

データ不足。

```text
7日平均を出すには、もう少し記録が必要です。
あと3日ほど入力すると、日々のブレではなく流れが見えてきます。
```

入力忘れ。

```text
昨日の分もあとから入力できます。
完璧に続けるより、戻ってこられることのほうが大事です。
```

## Acceptance criteria

- ユーザーは今日の体重を登録できる。
- ユーザーは過去日の体重を登録できる。
- ユーザーは体重記録を編集できる。
- ユーザーは体重記録を削除できる。
- グラフに日々の体重と7日移動平均が表示される。
- 7日移動平均はデータ不足時に誤解を招かない表示になる。
- 同日の複数入力時もグラフが破綻しない。
- 目標体重までの残りkgが表示される。
- 週次トレンドが理想範囲、横ばい、増加傾向などで判定される。
- コーチコメントがトレンドに応じて表示される。
- 体重が増えた日でも、コメントがユーザーを責めない。
- 入力はスマホで10秒以内に完了できる。
- タイムゾーンは日本時間を前提に日付処理する。

## Edge cases

- 旅行や飲み会後に一時的に1kg以上増える
- 塩分や糖質で水分量が増える
- 筋トレ後の筋肉痛で水分保持が起きる
- 入力を数日忘れる
- 小数点を間違えて入力する
- 同じ日に朝と夜の体重を両方入力する
- 体重が急激に落ちすぎる
