# 体重コーチ

スマホで使うことを前提にした、自分専用の減量管理PWAです。

このアプリは、毎日の体重だけを一喜一憂して見るのではなく、指数移動平均で計算した「トレンド体重」を主役にします。食事側は細かい量を入力せず、減量を崩しにくい行動チェックだけで評価します。

## 現在の主な機能

- カレンダーから日付を選んで記録できます。
- 実測体重を記録できます。
- トレンド体重を指数移動平均で表示します。
- 平日/休日で切り替わる食事チェックを記録できます。
- 運動実績を「休養」「実施」で記録できます。
- 運動画面で筋トレ、サンドバッグ、ランニングのメニューを自動生成できます。
- 運動メニューはソフト、ノーマル、ハードの強度を選べます。
- 運動メニューには概算消費カロリーを表示します。
- 日ごとの食事チェック点から○/△/×の判定を表示します。
- カレンダーの日付右上にランクバッジを表示します。
- 点数に応じて燃焼サマリの火力が10段階で変化します。
- データは端末内の `localStorage` に保存します。

## 画面構成

### 記録

日ごとの体重、運動実績、食事チェック、メモを記録する画面です。

カレンダーで過去日を選べるため、入力漏れや後からの修正にも対応できます。保存ボタンを押すと、その日の総合評価を表示します。

### 運動

その日に行う運動メニューを作る画面です。

対象は以下の3種類です。

- 筋トレ
- サンドバッグ
- ランニング

各種目ごとに実施するかをブレーカーUIで切り替え、強度をソフト、ノーマル、ハードから選びます。「最適メニューの自動生成」を押すと、その日のメニューと概算消費カロリーが作成されます。

### 推移

実測体重とトレンド体重の推移を見る画面です。

実測体重は日々の水分量、塩分、胃腸内容物で大きくぶれるため、評価の主役はトレンド体重にしています。

### 設定

身長、開始体重、目標体重、目標日を管理します。

## トレンド体重の計算

トレンド体重は指数移動平均で計算します。

初回記録日のトレンド体重は、その日の実測体重と同じです。

2回目以降は以下の式で更新します。

```text
前回トレンド + 0.25 * (今回実測 - 前回トレンド)
```

同じ日に体重を再入力した場合は、その日の実測値を更新し、トレンド系列も再計算します。

## 食事チェック評価の考え方

食事チェックは100点満点です。

平日は16時間断食を前提に、午前と午後で分けます。

```text
午前: 40点
午後: 60点
```

平日の配点は以下です。

```text
食事開始が12:00以降: 18点
断食中は無糖飲料のみ: 8点
1食目の米・パン・麺を通常量まで: 8点
1食目にたんぱく質の主役あり: 6点
最後の食事・飲み物が20:00まで: 20点
夕食の米・パン・麺を通常量まで: 14点
揚げ物・脂質多めを避けた: 10点
酒・甘い飲み物なし: 8点
予定外の間食・夜食なし: 8点
```

休日は16時間断食を評価せず、チートを連鎖させないことを重視します。

```text
朝からだらだら食べ続けなかった: 15点
最初の食事にたんぱく質あり: 10点
甘い飲み物を控えた: 10点
チートは1回に収めた: 24点
大盛り・替え玉・追加飯なし: 16点
夜食しなかった: 15点
野菜・汁物・海藻などのかさ増しあり: 10点
```

80点以上は減量日、65点以上は維持から微減ライン、50点未満は食事側の崩れ日として扱います。

## 燃焼サマリ

燃焼サマリは、その日の食事チェック点に応じて火力が変化します。

0点は消火状態です。1点から100点までは10点刻みで10段階に分かれます。

```text
0点: 火はついていません。
1〜10点: 火はつきかけています。
11〜20点: 火種はあります。
21〜30点: 弱火で燃えています。
31〜40点: 火力はまだ弱いです。
41〜50点: 中火に届きそうです。
51〜60点: 中火で燃えています。
61〜70点: しっかり燃えています。
71〜80点: 強い火力で燃えています。
81〜90点: 高火力で燃えています。
91〜100点: 最大火力で燃えています。
```

## データ保存について

現在のデータ保存先はブラウザの `localStorage` です。

保存キーは以下です。

```text
weightTracker:v1
```

直前データのバックアップも保存します。

```text
weightTracker:v1:backup
```

通常の画面改修やCSS変更では、体重や食事記録は消えません。保存キーを変えない限り、既存データは読み込まれます。

ただし、以下の場合はデータが失われる可能性があります。

- ブラウザのサイトデータを削除した場合
- 別のURLや別ドメインで開いた場合
- `localhost` から `github.io` へ移行した場合
- スマホを初期化した場合
- ブラウザを変更した場合

特に重要なのは、`localStorage` はURLごとに別管理されることです。

たとえば、以下は別データ扱いです。

```text
http://localhost:4175
https://hiropon0216.github.io/weight_loss_app/
```

GitHub Pagesでスマホ運用を始める場合、ローカル環境のデータは自動では引き継がれません。必要であれば、今後JSONエクスポート/インポート機能を追加するのが安全です。

## ローカルで起動する方法

リポジトリのフォルダで以下を実行します。

```powershell
py -m http.server 4175
```

ブラウザで以下を開きます。

```text
http://localhost:4175/index.html
```

開発中にキャッシュが残る場合は、`index.html?v=44` のようにクエリを付けて開きます。

## GitHub Pagesで完全無料運用する方法

このアプリは静的なHTML/CSS/JavaScriptだけで動くため、GitHub Pagesに向いています。

### 1. GitHubへpushする

ローカルで変更をコミットして、GitHubへpushします。

```powershell
git add app.js index.html styles.css sw.js README.md
git commit -m "Update weight coach PWA"
git push origin main
```

### 2. GitHub Pagesを有効化する

GitHubのリポジトリ画面で以下を操作します。

```text
Settings
Pages
Build and deployment
Source: Deploy from a branch
Branch: main
Folder: /root
Save
```

数分待つと、以下のようなURLで公開されます。

```text
https://hiropon0216.github.io/weight_loss_app/
```

### 3. スマホで開く

スマホのブラウザでGitHub PagesのURLを開きます。

### 4. ホーム画面に追加する

#### iPhoneの場合

Safariで開きます。

```text
共有ボタン
ホーム画面に追加
追加
```

#### Androidの場合

Chromeで開きます。

```text
メニュー
ホーム画面に追加
追加
```

これで、普通のアプリのようにホーム画面から起動できます。

## GitHub Pages運用時の注意点

### データはスマホ内に保存される

GitHub Pagesで公開しても、データはクラウドに保存されません。体重や食事記録は、そのスマホのブラウザ内に保存されます。

そのため、同じURLをPCで開いても、スマホの記録は見えません。

### スマホのブラウザを変えると別データになる

Safariで使ったデータはSafariに保存されます。Chromeで開くと別データです。

### URLが変わると別データになる

GitHub PagesのURL、独自ドメイン、localhostはすべて別データになります。

### iPhoneではSafari利用が無難

iPhoneでホーム画面追加を使う場合は、Safariで開くのが最も無難です。

## 更新運用

コードを変更したら、以下の流れで運用します。

```powershell
git status
git add app.js index.html styles.css sw.js README.md
git commit -m "Update app"
git push origin main
```

GitHub Pagesはpush後に自動で更新されます。反映まで数分かかることがあります。

反映されない場合は、以下を試します。

- スマホでページを再読み込みする
- URLに `?v=45` のようなクエリを付けて開く
- ホーム画面アプリを一度閉じて開き直す
- ブラウザのキャッシュを削除する
