# 体重コーチ

スマホで使うことを前提にした、自分専用の減量管理PWAです。

このアプリは、毎日の体重だけを一喜一憂して見るのではなく、指数移動平均で計算した「トレンド体重」を主役にします。食事チェックと運動実績を総合点として評価し、S/A/B/C/Dのランクと燃焼サマリで、減量に向いた行動を積み上げる設計です。

## 現在の主な機能

- カレンダーから日付を選んで記録できます。
- 実測体重を記録できます。
- トレンド体重を指数移動平均で表示します。
- 食事チェックを8項目で記録できます。
- 運動実績を「休養」「実施」で記録できます。
- 運動画面で筋トレ、サンドバッグ、ランニングのメニューを自動生成できます。
- 運動メニューはソフト、ノーマル、ハードの強度を選べます。
- 運動メニューには概算消費カロリーを表示します。
- 日ごとの総合点からS/A/B/C/Dのランクを表示します。
- カレンダーの日付右上にランクバッジを表示します。
- 点数に応じて燃焼サマリの火力が10段階で変化します。
- データは端末内の `localStorage` に保存します。

## 画面構成

### 記録

日ごとの体重、運動実績、食事チェック、メモを記録する画面です。

カレンダーで過去日を選べるため、入力漏れや後からの修正にも対応できます。保存ボタンを押すと、その日の総合評価を表示します。

### 運動

その日に行う運動メニューを作る画面です。

対象は以下の3種類です。

- 筋トレ
- サンドバッグ
- ランニング

各種目ごとに実施するかをブレーカーUIで切り替え、強度をソフト、ノーマル、ハードから選びます。「最適メニューの自動生成」を押すと、その日のメニューと概算消費カロリーが作成されます。

### 推移

実測体重とトレンド体重の推移を見る画面です。

実測体重は日々の水分量、塩分、胃腸内容物で大きくぶれるため、評価の主役はトレンド体重にしています。

### 設定

身長、開始体重、目標体重、目標日を管理します。

## トレンド体重の計算

トレンド体重は指数移動平均で計算します。

初回記録日のトレンド体重は、その日の実測体重と同じです。

2回目以降は以下の式で更新します。

```text
前回トレンド + 0.25 * (今回実測 - 前回トレンド)
```

同じ日に体重を再入力した場合は、その日の実測値を更新し、トレンド系列も再計算します。

## 総合評価の考え方

総合点は100点満点です。

現在の大枠は以下です。

```text
食事: 最大82点
運動: 最大18点
体重記録: 0点
```

体重記録は評価の前提データとして扱い、点数は付けません。減量では、運動よりも食事管理の影響が大きくなりやすいため、食事の配点を高くしています。運動は重要ですが、運動で食事の乱れを帳消しにする設計にはしていません。

### 食事チェック

食事チェックは減量に直結する項目を中心に、以下の8項目に絞っています。

- たんぱく質100g
- 米・麺・パンは1食150gまで
- 揚げ物なし
- お菓子なし
- 酒・ジュースなし
- 21時以降の食事なし
- 野菜を摂取
- 水・お茶1.5L以上

食事点は、純粋に体重を落とす目的への寄与が大きい順に重くしています。

```text
お菓子なし: 18点
酒・ジュースなし: 17点
米・麺・パンは1食150gまで: 15点
揚げ物なし: 14点
たんぱく質100g: 8点
21時以降の食事なし: 4点
野菜を摂取: 3点
水・お茶1.5L以上: 3点
```

### 運動点

運動点は、運動メニューの概算消費カロリーをもとに計算します。

計算式は以下です。

```text
kcal = MET × 3.5 × 体重kg × 分 ÷ 200
```

点数は概算消費カロリーから算出し、最大18点で上限を設けています。

上限を設けている理由は、運動量が多い日でも、食事管理が崩れている場合に高評価になりすぎないようにするためです。

## ランク

総合点から以下のランクを表示します。

```text
S: 92点以上
A: 82点以上
B: 70点以上
C: 55点以上
D: 55点未満
```

SとAは動きのある光沢エフェクトを表示します。SはAより希少性が高いため、金色の脈動と強いグローを追加しています。Dは雨のような暗い背景エフェクトを表示します。

## 燃焼サマリ

燃焼サマリは、その日の総合点に応じて火力が変化します。

0点は消火状態です。1点から100点までは10点刻みで10段階に分かれます。

```text
0点: 火はついていません。
1〜10点: 火はつきかけています。
11〜20点: 火種はあります。
21〜30点: 弱火で燃えています。
31〜40点: 火力はまだ弱いです。
41〜50点: 中火に届きそうです。
51〜60点: 中火で燃えています。
61〜70点: しっかり燃えています。
71〜80点: 強い火力で燃えています。
81〜90点: 高火力で燃えています。
91〜100点: 最大火力で燃えています。
```

## データ保存について

現在のデータ保存先はブラウザの `localStorage` です。

保存キーは以下です。

```text
weightTracker:v1
```

直前データのバックアップも保存します。

```text
weightTracker:v1:backup
```

通常の画面改修やCSS変更では、体重や食事記録は消えません。保存キーを変えない限り、既存データは読み込まれます。

ただし、以下の場合はデータが失われる可能性があります。

- ブラウザのサイトデータを削除した場合
- 別のURLや別ドメインで開いた場合
- `localhost` から `github.io` へ移行した場合
- スマホを初期化した場合
- ブラウザを変更した場合

特に重要なのは、`localStorage` はURLごとに別管理されることです。

たとえば、以下は別データ扱いです。

```text
http://localhost:4175
https://hiropon0216.github.io/weight_loss_app/
```

GitHub Pagesでスマホ運用を始める場合、ローカル環境のデータは自動では引き継がれません。必要であれば、今後JSONエクスポート/インポート機能を追加するのが安全です。

## ローカルで起動する方法

リポジトリのフォルダで以下を実行します。

```powershell
py -m http.server 4175
```

ブラウザで以下を開きます。

```text
http://localhost:4175/index.html
```

開発中にキャッシュが残る場合は、`index.html?v=44` のようにクエリを付けて開きます。

## GitHub Pagesで完全無料運用する方法

このアプリは静的なHTML/CSS/JavaScriptだけで動くため、GitHub Pagesに向いています。

### 1. GitHubへpushする

ローカルで変更をコミットして、GitHubへpushします。

```powershell
git add app.js index.html styles.css sw.js README.md
git commit -m "Update weight coach PWA"
git push origin main
```

### 2. GitHub Pagesを有効化する

GitHubのリポジトリ画面で以下を操作します。

```text
Settings
Pages
Build and deployment
Source: Deploy from a branch
Branch: main
Folder: /root
Save
```

数分待つと、以下のようなURLで公開されます。

```text
https://hiropon0216.github.io/weight_loss_app/
```

### 3. スマホで開く

スマホのブラウザでGitHub PagesのURLを開きます。

### 4. ホーム画面に追加する

#### iPhoneの場合

Safariで開きます。

```text
共有ボタン
ホーム画面に追加
追加
```

#### Androidの場合

Chromeで開きます。

```text
メニュー
ホーム画面に追加
追加
```

これで、普通のアプリのようにホーム画面から起動できます。

## GitHub Pages運用時の注意点

### データはスマホ内に保存される

GitHub Pagesで公開しても、データはクラウドに保存されません。体重や食事記録は、そのスマホのブラウザ内に保存されます。

そのため、同じURLをPCで開いても、スマホの記録は見えません。

### スマホのブラウザを変えると別データになる

Safariで使ったデータはSafariに保存されます。Chromeで開くと別データです。

### URLが変わると別データになる

GitHub PagesのURL、独自ドメイン、localhostはすべて別データになります。

### iPhoneではSafari利用が無難

iPhoneでホーム画面追加を使う場合は、Safariで開くのが最も無難です。

## 更新運用

コードを変更したら、以下の流れで運用します。

```powershell
git status
git add app.js index.html styles.css sw.js README.md
git commit -m "Update app"
git push origin main
```

GitHub Pagesはpush後に自動で更新されます。反映まで数分かかることがあります。

反映されない場合は、以下を試します。

- スマホでページを再読み込みする
- URLに `?v=45` のようなクエリを付けて開く
- ホーム画面アプリを一度閉じて開き直す
- ブラウザのキャッシュを削除する
